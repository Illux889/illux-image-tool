# v0.2 decisions (2026-11-04)

Rulings taken while building v0.2 (resample range, size-based rules, macOS), in order. Same format as the v0.1 decisions: what was decided, why, and what it costs if wrong. The Windows rulings R1-R47 of [2026-10-23-build-decisions.md](2026-10-23-build-decisions.md) still apply.

- V1 Task 2 only changed the WinForms settings code as far as needed to compile (Upsample became Resample, the per-folder ppi field went away). The real UI work came in Tasks 6 and 7. Cost: none.
- V2 User rule: nothing is installed, elevated or registered on the user's PC. Installer, service and macOS behaviour are tested only on GitHub Actions. `feat/v0.2` may be pushed; no tags, releases or main until the user says so. Cost: less local testing.
- V3 Task 2's extra edits were accepted: a warnings parameter on BatchRunner, the `.bat` script joins `resample=N` so the clear error shows, and the smoke test expects the 300 ppi Small default. Cost: none.
- V4 On macOS, `RunLock.AnyActive` (run by the root daemon) ignores everything that is not a regular file and never blocks. Otherwise a FIFO or socket planted in the world-writable `runs/` folder would stop updates. Stale cleanup in `RunLock.Acquire` got the same non-blocking probe. Cost: none.
- V5 The macOS download folder is also checked for its owner (root or an admin-group owner), like the other trusted folders. Cost: small.
- V6 Four Task 4 hardening minors were folded into Task 5: check owner and mode of Root before touching `run/`; a file with more than one hard link is not a lock; the client socket is created inside the try and a `SocketException` is caught; the updater error text no longer names Windows. Cost: a slightly larger diff.
- V7 On macOS, Root stays root-owned 0755. The Settings app saves `config.json` (root:admin 0664) by writing the existing file in place: open without following links, write from offset 0, then truncate to the new length. It never writes temp-and-move in Root, because that would need write access to Root and would open the socket and the updates to tampering. A torn write is covered by the existing rule: an invalid config makes the service keep the last good rules (CLI: defaults plus a Warning). Cost if wrong: rework of the Mac save path.
- V8 On macOS the Settings window shows a one-line "service log is admin-only" note with its path instead of reading `service-logs/` (root 0700), because the window runs as the user. Cost: small UI change.
- V9 macOS Start is `launchctl bootstrap` of the daemon plist (an already-loaded error is ignored) followed by `kickstart -k`, in one admin prompt. Stop stays `bootout`. Kickstart alone cannot start a daemon that was booted out. Cost: small string change.
- V10 The tray icon opens settings with a single click (Avalonia's tray icon has no double-click), and tray messages are small windows. Kept as is and named in the release notes. Cost if wrong: stray settings windows or UAC prompts on Windows.
- V11 On macOS, non-admins get read-only folders and rules, but Start/Stop stay enabled (they ask for admin credentials themselves) and Check/Update now stay enabled, like the non-elevated Windows tray. Cost: none.
- V12 Rule number inputs accept "," or "." as the decimal separator and no thousands separators. Unparsable input shows a short message; out-of-range input shows the validation message instead of being clamped. Made for Danish users (da-DK). Cost: small parse change.
- V13 A daemon-started Mac update cannot run end to end in CI (host allow-list, no production test hooks). The smoke test checks `AbandonProcessGroup` with `plutil` and simulates the update with a throw-away LaunchDaemon that has the same flag and the same shell and installer line. The first true end-to-end Mac "Update now" is therefore the one after v0.2.0. Cost: that first real update is the first full test; the user is told.
- V14 `config.json` in-place save no longer requires a link count of 1: a local user can hard-link the root-owned file into the world-writable `logs/` and block admin saves that way. Instead, Root must be root-owned with no group/other write before the write. Only root can create entries in a trusted Root, so a link count adds nothing. Cost if wrong: small revert.
- V15 On macOS the watched folders no longer run as root. The final review found that the root daemon handled user-writable watched folders with path-based .NET file APIs written for Windows ACL semantics: a hard link planted as `Out/_warnings.log` gave root code execution (C1), the per-file temp folder in Out could be swapped (C2), a FIFO in In hung every folder (I1), and ImageMagick's temp was the squattable `/tmp/IlluxImageTool` (I2). The service is now two launchd jobs running the same Watcher binary: `dk.illux.imagetool.watcher` (root, `--role updates`: control socket and updates only, TMPDIR `Root/work/`) and `dk.illux.imagetool.folders` (`--role folders`, watched folders only, `UserName` = the folder account, TMPDIR `Root/folder-work/`, logs in `Root/folder-logs/`). The folder account is the console user (uid >= 501) at the first install, kept in `Root/folder-account` and never re-picked by an upgrade; without one the folders job is not set up and Settings says so. The macOS watcher refuses to run without a role; Windows takes no role and keeps one service. The folders job takes a RunLock in `runs/` while it works, so the root updater still waits for it (R30). Hardening on top: O_NOFOLLOW appends with an fstat owner/link-count check, staging in `folder-work/` with an exclusive rename, lstat-only regular files from In, a checked ImageMagick temp folder, a stale-flag check every minute, and control characters stripped from logged file names (both OSes). **Deviation from spec §6.3**, which says "LaunchDaemon running as root": only the update/socket job still runs as root. Why: a root process cannot safely do path-based file work in folders that ordinary users can change, and the folder account has no rights beyond what its user already has. Cost: the watched folders need an account chosen at install (re-picking it means uninstall, delete `folder-account`, install again) and that account needs access to the folders; a Mac installed with nobody logged in has watched folders off until reinstalled.
- Other: the macOS save path writes from offset 0 and then truncates (V7 refined), so the file is never empty during a save.
- Other: if the daemon crashes and leaves a stale socket, the client reports "busy" until launchd restarts the daemon. Accepted (Task 6).
- Other: the macOS upgrade-test package is version 0.0.<run+1> in CI (a four-part version parses as three-part); the release builds X.Y.(Z+1) for the same test and never publishes it.
- Task 10 implementation note (not a ledger ruling): the release is one release with four files, made only after Windows and macOS both built and passed their smoke tests; a mismatch or missing file refuses the whole release. A manual run of the workflow is a dry run that does everything except create the release.

## Parked / known gaps (not fixed in v0.2)

- No rollback in the Mac preinstall. Recovery: run the `.pkg` again.
- Mac network shares and `/Volumes/<share>` are not supported; the default Originals folder for such a path would land on the boot disk. Desktop, Documents, Downloads and external drives are also unsupported.
- The Mac package is unsigned (ad-hoc only), so every user does the one-time Open Anyway step. No `/usr/local/bin` link and no package icon.
- A stale socket after a daemon crash reports "busy" until launchd restarts the daemon.
- First true Mac "Update now" is exercised only on the release after v0.2.0.
- The Mac uninstall script does not source `common.sh`; some planted-file test cases are still missing.
- Task 3 leftovers: the otool dependency guard only rejects `jpeg`; the CMake CMP0219 warning; the "logged once" stale-cleanup notice is untested; UpdateWorker not-retried half + state-not-writable lack macOS coverage; `FileIdentity` SetLastError unused.
- An unanchored `SETTINGS_PATTERN` in the uninstall's `pkill` (negligible).
- Settings: the Folders list is a fixed 150 px; duplicate rule names are not checked.
