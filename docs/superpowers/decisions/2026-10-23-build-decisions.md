# Build decisions (2026-10-23)

Decisions taken during the build on Illux's behalf, in order. Each line: what was decided — why — what it costs if wrong.

- R1 test project targets `net10.0-windows` from Task 1 (Core stays net10.0) — later tasks reference Watcher/Settings projects — cost if wrong: trivial retarget.
- R2 BatchRunner creates the output folder if it does not exist; if creation fails every file is Error with a readable message — AE always passes an existing folder, watcher folders may be new — cost if wrong: small behaviour change.
- R3 Task 9 may modify `src/Illux.ImageTool.Cli/CliApp.cs` for the two `ae` log lines — plan text in T9 requires it — cost: none.
- R4 `WatcherConfig.CheckForUpdates` (default true) is honoured by UpdateWorker: when false, no periodic checks; `check-now.flag` still works. No UI toggle (editable in config.json) — spec 11a has no toggle; keep field for servers without internet — cost if wrong: add a checkbox later.
- R5 EventLog writes are best-effort: logger provider creates source `Illux Image Tool` when possible (service runs as LocalSystem) and silently skips EventLog if not permitted; file log always written — tests run non-admin — cost if wrong: missing Event Log entries.
- R6 namespaces follow folders (Illux.ImageTool.<Folder>), classic .sln, xUnit 2.9.3 — implementer's choice in T1, consistent and conventional — cost if wrong: trivial rename.
- R7 Co-Authored-By trailer may name the subagent's actual model (harness rule) — attribution accuracy — cost: none.
- R8 ';' inside file names and colon-separated relative paths are not supported in %1 — Esko's own format is ';'-separated, so such names are inherently ambiguous — cost if wrong: rare file mis-split, shows as Error.
- R9 Magick.NET-Q16-HDRI-x64 pinned 14.17.2 (newest 14.x, no advisory); 15.x not adopted (major bump) — cost if wrong: later upgrade.
- R10 incomplete/invalid ICC chunk set (missing, duplicate, seq 0, count mismatch) → JpegInfo.IccProfile = null (treated as 'no profile', PDF falls back to Device colour space) — never embed a corrupt profile — cost if wrong: PDF loses a damaged profile that was unusable anyway.
- R11 jpegtran.exe/jpeg62.dll (and Magick.NET native) need the VC++ 2015-2022 x64 runtime: Task 14 installer bundles Microsoft's vc_redist.x64.exe (downloaded by build script from https://aka.ms/vs/17/release/vc_redist.x64.exe) and runs it '/install /quiet /norestart' when HKLM\SOFTWARE\Microsoft\VisualStudio\14.0\VC\Runtimes\x64 Installed != 1 — clean servers would otherwise fail with 0xC0000135 — cost if wrong: ~25 MB larger installer.
- R12 (overrides plan T4 '-outfile <out> <in>'): JpegTran streams the input file into jpegtran's stdin and writes stdout to a .NET FileStream (args: '-copy all' only) — jpegtran's ANSI argv breaks/misroutes non-cp1252 names and >260-char paths; .NET then owns cleanup — cost if wrong: none known (libjpeg-turbo sets binary stdio on Windows).
- R13 upsample raises only axes below target; axes already >= target keep their ppi and pixel count (150x300 -> 200x300) — spec non-goal 'no downsampling' outranks 'per axis to the target' — cost if wrong: rare non-square files keep non-square ppi.
- R14 re-encoded JPEG keeps its original progressive/baseline coding when the Baseline operation is off — spec anti-goal 'changing anything not asked' — cost: none.
- R15 GIF/BMP without a density field: FinalResolution still reports the computed ppi (needed for PDF page size); file itself cannot store it — cost: none.
- R16 resolution read order 8BIM 0x03ED > EXIF > header density (community-observed Photoshop order, cited in code); confirm on a real Photoshop file during user testing — cost if wrong: wrong ppi on files whose tags disagree.
- R17 ImageMagick reads/writes go through .NET FileStreams (long/UNC paths), and an upsample whose target exceeds 65,000 px on either axis (JPEG limit 65,535) is an Error before any work — reviewer found 290-char path failure and unbounded 200x upscale from 1-ppi files — cost if wrong: none.
- R18 palette images (PNG/GIF/BMP) become true colour when resampled (palette cannot hold new colours); bilevel becomes grayscale — colour model change only when pixels are rewritten — cost if wrong: larger files.
- R19 pages larger than 14,400 pt on either side use /UserUnit (PDF 1.6 feature): UserUnit = smallest integer making both sides <= 14,400, box values divided by it — large-format prints (>5.08 m) are plausible at Illux — cost if wrong: none.
- R20 test package is 'PdfPig' 0.1.16 (official id; namespaces UglyToad.PdfPig) — plan named the namespace, not the id — cost: none.
- R21 32-bit float images (8bit op off) written as 16-bit in PDF; Lab/YCbCr colour spaces → NotSupportedException (clear Error) — PDF has no float samples — cost if wrong: rare.
- R22 error messages may include full file paths — the log is internal (AE task log / local log), paths are needed to diagnose; no secrets involved — cost: none.
- R23 USER RULE — no PC changes outside repo/temp: Task 12/13/14 manual checks (sc create, installer install/upgrade, Inno Setup local install) move to GitHub Actions windows runner or to the user's own test; already installed earlier: GitHub CLI (by controller), 7-Zip (by T4 implementer), pypdf in %TEMP%\ilxpdf (controller) — cost: less local verification.
- R24 missingppi accepts '72|skip|error' (spec wording), 'assume72' dropped; RunLock creation failure is best-effort (logged, run continues) — a processing run must not fail because of update bookkeeping; installer grants Users modify on ProgramData — cost if wrong: an update could start during a run whose lock failed.
- R25 assume Esko quotes each Run Script argument (its own batch example relies on %1 containing ';'); the bat additionally rejoins key/value pairs that cmd split on '=' (output/quality/filter/missingppi + upsample followed by a number); PowerShell script is the recommended one; first real AE test confirms via the 'Inputs:' log line — cost if wrong: bat users must quote params.
- R26 both AE scripts map any exit code other than 0/1 to 2; installer (T14) places scripts in '%ProgramFiles%\Illux Image Tool\scripts\ae' and the guide points there — cost: none.
- R27 Updater startInstaller is Func<string installerPath, string arguments, Process?>; CheckAsync swallows network/JSON errors (warning logged, state unchanged); T12 UpdateWorker must serialise InstallAsync calls — plan's single-arg delegate couldn't carry args — cost: none.
- R28 updater security: default download dir = AppPaths.Root\update created with an explicit SYSTEM+Administrators-only ACL (inheritance off); refuse a download dir that is a reparse point or not owned by SYSTEM/Administrators (except in tests via an explicit opt-out flag on the test constructor); re-hash the installer from disk while holding a FileShare.Read handle until the process has started; asset hosts limited to github.com / *.githubusercontent.com; flag written then idle re-checked — LocalSystem launching an exe from a user-writable folder is a privilege-escalation path — cost: none.
- R29 ProgramData layout/ACL (applies to T12-T14): Root owned by Administrators with a protected ACL — SYSTEM/Admins full, Users read; Users-modify only on subfolders runs\, logs\, requests\ and on the file config.json; update\ SYSTEM/Admins only; request flags (check-now.flag, install-now.flag) live in Root\requests\; updating.flag and update-state.json in Root (SYSTEM-written, user-readable) — prevents users renaming/squatting update\ or the root — cost if wrong: settings window can't write somewhere (caught in testing).
- R30 CLI, after acquiring its RunLock, checks updating.flag; if present it releases the lock and waits (same 5 s / 10 min rule as the scripts) before re-acquiring — closes the wrapper-check→lock race — cost: none.
- R31 stale updating.flag: the installer deletes the flag BEFORE starting the service (T14); at startup the watcher deletes updating.flag only if it is older than 15 min and no process named 'IlluxImageTool-Setup-*' is running — avoids a crash/reboot blocking AE runs forever — cost if wrong: an update window could open early (installer re-check makes this harmless).
- R32 installer (T14) registers the EventLog source 'Illux Image Tool' (admin context); service keeps best-effort logging; UpdateWorker single loop (serialised install, check-now waits during an install idle-wait) accepted — cost: delayed check-now during an install.
- R33 ConfigStore.Save gets a short retry on UnauthorizedAccess/IOException (like UpdateStateStore.Save) — assigned to Task 13, since the settings window is the writer that races the service's reads — cost: none.
- R34 (amends R29) config.json is NOT user-writable: Root ACL SYSTEM/Admins full, Users read (config.json inherits); the settings WINDOW self-elevates at start (relaunch runas unless already elevated; --tray stays non-elevated); requests\ stays Users-modify so the tray's Update now / Check work without admin — a user-editable config would let any user make the LocalSystem service write/move files anywhere (privilege escalation) — cost: a UAC prompt when opening settings.
- R35 USER RULE means Inno Setup is never installed locally: Task 14 installer is built and smoke-tested (silent install, upgrade, uninstall, ACL assertions) only on GitHub Actions windows runners; Task 14 therefore also writes ci.yml (build/test + installer artifact + smoke test). The implementer may push branch feat/v1 and watch runs with gh. Creating a GitHub Release / tag and merging to main are publish actions → controller stops and asks the user — cost: user gets the test installer as a CI artifact first.
- R36 updater passes /LOG into AppPaths.Root\update\ (SYSTEM/Admins only), not logs\ — SYSTEM writing a predictable file in a user-writable folder is a symlink/hardlink attack path — cost: users can't read the installer log without admin.
- R37 service<->UI signals use named kernel events created by the service (Global\IlluxImageTool.CheckNow / .InstallNow; DACL SYSTEM+Admins full, Interactive Users SYNCHRONIZE|EVENT_MODIFY_STATE) instead of flag files in requests\; installer stops creating requests\ — removes SYSTEM file deletes in a user-writable folder (C1) — cost: Update now/Check only work while the service runs (already the UI rule).
- R38 service + elevated settings logs go to AppPaths.Root\service-logs\ (SYSTEM/Admins only, created by installer with the protected-DACL pattern); CLI keeps logs\ (runs as the AE user) — C1 — cost: users need admin to read service logs.
- R39 RunLock.AnyActive is read-only for privileged callers: skip reparse points, never delete; stale-lock cleanup only in the CLI (user context) — C1 — cost: stale locks linger until the next CLI run (they're ignored once openable).
- R40 FileProcessor: any target path equal to the input path → Error, never replace an original (C2).
- R41 PDF honours EXIF orientation 1-8 via the page transform matrix and swapped page size; pixels/JPEG bytes untouched (I1).
- R42 watcher pauses picking up new files while updating.flag exists, and on startup removes '.illux-tmp-*' folders older than 1 hour in configured Out folders (I2).
- R43 a named service account must be a local Administrator (needed for updates and update\ ACL): stated in the account dialog and docs (I3).
- R44 watcher refuses to write/move into a destination folder that is a reparse point (other than the configured folder path itself) or onto an existing reparse-point file (I4); residual TOCTOU accepted and documented.
- R45 CI build versions become 0.0.<run_number> so real releases (0.1.0+) are always newer (I6).
Final: open — N1 (Important, security): RemoveStaleTempFolders as SYSTEM recursively deletes user-plantable .illux-tmp-* in Out (junction swap → arbitrary delete). Ruling: surfaced to user with recommendation (only clean temp folders the service itself created with a protected ACL, or drop the cleanup) — no second fix wave per process.
