# Illux Image Tool v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Size-based resampling rules (up and down, bicubic) configurable in Settings, and a macOS (Apple silicon) build with watched folders, Settings/menu-bar app and click-to-update — without breaking Windows.

**Architecture:** Core gains `ResolutionRule`s stored in `config.json` and used by `ImagePipeline` instead of a single target ppi. Platform-specific pieces (paths, permissions, service host, service signals, installer launch, jpegtran binary) get a macOS implementation next to the existing Windows one. The WinForms Settings app is ported to Avalonia so one UI runs on both. A macOS `.pkg` (LaunchDaemon + LaunchAgent + app) is built and smoke-tested on GitHub's Apple-silicon runner and published in the same release as the Windows installer.

**Tech Stack:** .NET 10, Magick.NET-Q16-HDRI-AnyCPU 14.17.2 (has `osx-arm64` + `win-x64` natives — verified), Avalonia 12.1.x (newest stable), libjpeg-turbo 3.2.0, Inno Setup 6 (Windows), `pkgbuild`/`productbuild` (macOS), GitHub Actions `windows-latest` + `macos-15` (arm64).

**Spec:** `docs/superpowers/specs/2026-11-04-v0.2-resample-range-and-mac-design.md` (builds on the v0.1 spec and `docs/superpowers/decisions/2026-10-23-build-decisions.md`).

## Global Constraints

- Default rules exactly: 1) `Small` — fitsWithin 40 × 30 cm → target 300, leave alone 250–350; 2) `Large` — all → target 200, leave alone 150–250.
- Rule validation: whole-number ppi, `1 ≤ minPpi ≤ targetPpi ≤ maxPpi ≤ 2400`; sizes 0.1–1000 cm (area 0.01–1,000,000 cm²); exactly one `all` rule and it is last.
- Per-axis decision: an axis is resampled to target iff its ppi < minPpi or > maxPpi (0.05 ppi tolerance as today); physical size kept; >4× enlargement → Warning; >65,000 px → Error (unchanged).
- Print size in cm = pixels ÷ ppi × 2.54 per axis; missing ppi → existing `missingppi` policy (assume 72 by default).
- Default filter Bicubic (= ImageMagick `Catrom`); `filter=lanczos|mitchell|bicubic` still accepted.
- AE operation `resample`, alias `upsample`; any `resample=…`/`upsample=…` → ParameterException with exactly: `ppi is set in Illux Image Tool Settings (Resolution rules), not in the AE ticket`.
- No code ever creates or edits watched folders on its own; no migration of folders/tickets.
- macOS: Apple silicon only, macOS 15+; unsigned (ad-hoc signatures only); data folder `/Library/Application Support/Illux Image Tool/`; daemon label `dk.illux.imagetool.watcher`; tray LaunchAgent label `dk.illux.imagetool.tray`; asset `IlluxImageTool-X.Y.Z-macOS-arm64.pkg` + `.sha256`.
- Windows asset name unchanged: `IlluxImageTool-Setup-X.Y.Z.exe` + `.sha256` (v0.1.0's updater must find v0.2.0). Windows security rulings R1–R47 unchanged.
- HARD RULE (user): nothing is installed/run elevated/registered on the user's PC; installer, service and macOS behaviour are verified only on GitHub Actions runners. Push `feat/v0.2` allowed; no tags/releases/main until the user says so.
- Commits: conventional, with the model's `Co-Authored-By:` trailer.

## Review Focus

1. **No stored ppi** → assumed 72 ppi makes the print size huge → rule `Large` → 200 ppi, with the "assumed 72" Warning (Task 2 `Plan_NoPpi_UsesAssumed72_LargeRule`).
2. **Non-square ppi with one axis inside the range** (e.g. 300 × 120 ppi, Large) → only the 120 axis changes (Task 2 `Plan_OnlyOutOfRangeAxisChanges`).
3. **Exact boundary** 40.0 × 30.0 cm (and rotated 30 × 40) counts as fitting → `Small` (Task 1 `FitsWithin_BoundaryAndRotation`).
4. **A v0.1 `config.json` with no `resolutionRules`** loads with the defaults and is not rewritten by the service (Task 1 `Load_V01Config_UsesDefaultRules`).
5. **v0.1.0 Windows install finds the v0.2.0 release** — the Windows asset name and checksum format are unchanged and a release with extra macOS assets still resolves (Task 5 `Latest_WithMacAssets_WindowsStillResolves`).
