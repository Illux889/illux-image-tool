# Illux Image Tool — PDF input Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A PDF dropped into a watched folder or passed by AE comes out as one PDF in which every image has been
through the normal pipeline (8 bit, size rules with bicubic scaling, baseline JPEG), with pages, page sizes and
placements unchanged.

**Architecture:** A new `Pdf/Input` area in Core does four things. It reads the PDF and finds every drawn image with
its drawn size (PdfPig). It turns each image into a temporary image file that carries the ppi the image is drawn at.
It runs the existing `ImagePipeline` on that file. It writes the results back as new image streams in a rewritten
PDF. `FileProcessor` sends PDF inputs (detected by content) down this path. The library used to write the PDF is
chosen by a spike in Task 1. Everything after Task 1 sits behind one interface, so only Task 5 (and Task 7, if QPDF
is chosen) depends on that choice.

**Tech Stack:** .NET 10, PdfPig (Apache 2.0, already a test dependency at 0.1.16, moves into Core at the newest
stable version), Magick.NET-Q16-HDRI-AnyCPU 14.17.2, and possibly QPDF 11+ (Apache 2.0, bundled like jpegtran) if
Task 1 picks it.

**Spec:** `docs/superpowers/specs/2026-11-05-pdf-input-design.md` (builds on the v0.2 spec and the rulings in
`docs/superpowers/decisions/`).

## Global Constraints

- Licences: MIT, BSD or Apache 2.0 only. PDFsharp is excluded (AGPL / commercial).
- No new settings and no new AE parameters. The existing operations, resolution rules, filter, JPEG quality and name
  policies apply to images inside PDFs.
- A PDF in gives exactly one PDF out, with the input's base name and extension, whatever `output=` says
  (`same`/`pdf`/`both`). No image files come out of a PDF.
- The drawn size of an image is the length of its two image axes after the full transformation (page content, form
  `/Matrix`, nested `cm`), in cm. Per axis: ppi = pixels ÷ (drawn length in inches). From here the existing `Plan`
  logic decides: the rule picked from the drawn size, per-axis range test (ruling R13), >4× enlargement → Warning,
  >65,000 px → Error.
- Page content, page boxes, fonts, annotations, metadata and output intents are never changed. The output's PDF
  version is never lower than the input's.
- An image needing no change keeps its stream byte for byte. If no image needs a change, the output file is a byte
  copy of the input and the message is `no change needed`.
- Any failure on any image → the whole PDF goes to Error and nothing is written to Out.
- Messages are prefixed `page N, image M: ` (1-based, M counts the distinct images drawn on that page in drawing
  order). Overall status is worked out as for image files.
- Error messages, exactly:
  - `encrypted PDFs are not supported`
  - `the PDF could not be read (<reason>)`
  - `page N, image M: <what> is not supported`, where <what> is one of: `a soft mask with /Matte`,
    `JPEG 2000 with its own mask`, `a colour-key mask on an image that needs scaling`,
    `a stencil mask that needs scaling`, `<filter> image data`
- Warnings, exactly:
  - `no images found`
  - `N inline image(s) not processed`
  - `page N, image M: drawn at different sizes; processed for the largest (W × H cm)`
- Windows x64 and macOS arm64. CI on both, and the install smoke tests on both push one PDF through a watched folder.
- HARD RULE (user): nothing is installed, run elevated or registered on the user's PC. Installer, service and macOS
  behaviour are verified only on GitHub Actions. Pushing `feat/pdf-input` is allowed. No tags, no releases and nothing
  to main until the user says so.
- Commits: conventional, with the model's `Co-Authored-By:` trailer.

## Review Focus

1. **Image drawn rotated 90°**: the image's width axis runs up the page. ppi must come from the image's own axes, not
   the page's x/y (Task 2 `Scan_Rotated90_UsesImageAxes`).
2. **Chili PDFs are not PDF 1.6**: the output check in `FolderScanner.VerifyOutputs` must accept any `%PDF-1.x` and
   `%PDF-2.0` header, not only `%PDF-1.6` (Task 6 `VerifyOutputs_AcceptsAnyPdfVersion`).
3. **CMYK JPEG (Adobe APP14) with `/Decode [1 0 1 0 1 0 1 0]`**: after scaling, the colour space and decode array are
   unchanged and the colours are not inverted (Task 4 `RoundTrip_CmykJpeg_KeepsDecodeAndColours`).
4. **Image with a soft mask that gets scaled**: the mask is scaled by the same factors and stays aligned (Task 4
   `RoundTrip_SoftMask_ScaledBySameFactors`).
5. **One image used on two pages at different sizes**: processed once at the largest size, with the Warning (Task 2
   `Scan_ReusedAtTwoSizes_LargestAndFlag`, Task 6 `Pdf_ReusedImage_ProcessedOnceWithWarning`).

### Task 4: Image stream ⇄ temporary image file

**Files:**
- Create: `src/Illux.ImageTool.Core/Pdf/Input/PdfImageExtractor.cs`, `src/Illux.ImageTool.Core/Pdf/Input/PdfImageEncoder.cs`, `src/Illux.ImageTool.Core/Pdf/Input/PdfImageStream.cs`
- Test: `tests/Illux.ImageTool.Tests/PdfImageRoundTripTests.cs`

**Interfaces:**
- Consumes: `PdfObjectId`, `PdfScan` (Task 2).
- Produces:
  - `sealed record PdfImageStream(byte[] Dictionary, byte[] Data)`: a replacement image object. `Dictionary` is the
    serialised dictionary, so P1's writer can use it unchanged. The soft mask's replacement is a second
    `PdfImageStream`.
  - `sealed record ExtractedImage(string Path, bool IsJpeg, string? SoftMaskPath)`
  - `static ExtractedImage PdfImageExtractor.Extract(PdfDocument doc, PdfObjectId image, bool needsScaling, string tempDir)`:
    - DCT data is written byte for byte as `.jpg`.
    - Everything else is decoded to raw samples and written as a lossless TIFF in the same colour space, at its own
      bit depth (1/8/16), with the ICC profile attached when the colour space is ICCBased.
    - Indexed images are expanded to the base colour space.
    - The soft mask is written as an 8/16-bit gray TIFF.
    - It throws `UnsupportedImageException` with the exact Global Constraints messages: `/Matte`, `/SMaskInData`,
      colour-key `/Mask` and `/ImageMask` (the last two only when `needsScaling`), and filters ImageMagick cannot
      decode.
  - `static (PdfImageStream Image, PdfImageStream? SoftMask) PdfImageEncoder.Encode(PdfDocument doc, PdfObjectId image, string processedPath, ExtractedImage extracted, (double X, double Y) factors)`:
    - Builds the new dictionary from the old one. Only these change: `/Width`, `/Height`, `/BitsPerComponent`,
      `/Filter`, `/DecodeParms`, `/Length`, and `/ColorSpace` only when Indexed was expanded.
    - The data is DCT straight from a processed `.jpg`, or Flate of the processed samples otherwise.
    - The soft mask (if any) is scaled by `factors` with the configured filter and encoded as a Flate gray image.
- [ ] **Step 1:** Write the failing tests. Each one extracts, scales by a known factor with `MagickImage.Resize`, and
  encodes, then checks the result through PdfPig:
  - `RoundTrip_RgbJpeg_DctKept`
  - `RoundTrip_CmykJpeg_KeepsDecodeAndColours`: compare a patch colour before and after, ΔE < 2.
  - `RoundTrip_Flate16BitRgb`
  - `RoundTrip_GrayIcc_KeepsProfile`
  - `RoundTrip_Indexed_ExpandedSameColours`
  - `RoundTrip_SoftMask_ScaledBySameFactors`
  - `Extract_Matte_Throws`
  - `Extract_ImageMaskNeedingScale_Throws`
  - `Encode_UnchangedKeysPreserved`: e.g. `/Interpolate`, `/Intent` and unknown keys stay.
- [ ] **Step 2:** Run them and see them FAIL. **Step 3:** Implement. **Step 4:** PASS, full suite green.

### Task 6: PDF pipeline and wiring

  whatever `output=`), `src/Illux.ImageTool.Core/Watch/FolderScanner.cs` (`LooksLikePdf` accepts `%PDF-1.0`–`%PDF-1.7`
  and `%PDF-2.0`), `src/Illux.ImageTool.Cli/CliHelp.cs`, `docs/ae-setup.md`, `README.md`

- Test: `tests/Illux.ImageTool.Tests/PdfPipelineTests.cs`, extend `BatchTests.cs`, `WatcherTests.cs`, `CliTests.cs`

**Interfaces:**
- Consumes: Tasks 2–5.
- Produces: `static Task<PipelineResult> PdfPipeline.RunAsync(string inputPdf, string outputPdf, ProcessingOptions options, CancellationToken ct)`.
  The steps, in order:
  1. Scan.
  2. Plan each image with `ImagePipeline.Plan` on a `SourceImage` built from the stream dictionary and the drawn
     resolution: Format Jpeg (with `JpegInspector` run on the raw DCT bytes, for progressive detection) or Tiff,
     Depth = `/BitsPerComponent`. Nothing is decoded for images that need no change.
  3. If no image needs a change, byte copy and `no change needed`.
  4. Otherwise extract, run `ImagePipeline.RunAsync` with the drawn resolution, and encode each image that needs a
     change, all in a temp folder under the caller's temp dir.
  5. Rewrite.
  6. Messages are prefixed `page N, image M: `. Status is the worst one.
  7. `FinalResolution` is the lowest final ppi of any image. It is used only for logs.
