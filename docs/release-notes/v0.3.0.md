## What's new in 0.3.0

- **PDF files are accepted.** Drop a PDF into a watched folder or send it through Automation Engine, as you do with an image. The tool takes every image in the PDF, does exactly what it does to an image file (8 bit, resampling by the Resolution rules, baseline JPEG), and puts it back. Made for PDFs from CHILI Publish.
- **The PDF stays the same size.** Same pages, same page sizes, each image in the same place at the same size. Only the number of pixels in the images changes. Nothing else in the PDF is touched.
- **The ppi of an image in a PDF** is its pixels divided by the size it is drawn on the page. That size picks the Resolution rule, as the print size does for an image file.
- **A PDF in gives one PDF out**, with the same name. The `output=` setting (`same`, `pdf`, `both`) makes no difference for a PDF.
- **Messages name the page and the image**, for example `page 1, image 1: 120→200 ppi (rule "Large": 61.0 × 45.7 cm; 2882×2159 → 4803×3598, bicubic)`.

When a PDF goes to Error, nothing is written to Out for it:

- encrypted or signed PDFs;
- a PDF that cannot be read;
- any image in it that cannot be processed (the message says which page and image).

Warnings: a PDF with no images is copied unchanged ("no images found"); small images written straight into the page are not processed ("1 inline image(s) not processed"); an image used at different sizes is processed once, for its largest size. If no image needs a change, the PDF is copied unchanged ("no change needed").

No new settings. The Resolution rules and the AE parameters work as before.

Files: `IlluxImageTool-Setup-0.3.0.exe` (Windows) and `IlluxImageTool-0.3.0-macOS-arm64.pkg` (macOS), each with a `.sha256` file.
